# VisitsPakistan --- Standalone Server Infrastructure

## Deployment Principle

Initial production runs on a **standalone Hetzner Ubuntu LTS server** using
Docker Compose and Nginx. Kubernetes and managed application platforms
are deliberately deferred. Components remain portable for later
separation.

## Starting Capacity Class

Validate by load testing; a practical initial class is 8--16 vCPU,
32--64 GB RAM and NVMe storage with capacity reserved for PostgreSQL,
OpenSearch and media. Use a static public IP and an off-server backup
destination.

## Public Network

Internet → Firewall → Nginx → frontend/API/CMS. Only 80/443 are public.
Restrict SSH by key and allowlist/VPN. PostgreSQL, Redis and OpenSearch
are private Docker-network services.

## Runtime Services

`nginx`, `frontend`, `api`, `worker`, `cms`, `postgres`, `redis-cache`, `redis-queue`,
`opensearch`.

## Frontend

Next.js App Router. `next build` creates the production application. Public
SEO routes use SSR or static generation/revalidation. Nginx serves immutable static assets with
long cache headers and proxies SSR/API traffic.

## API

NestJS behind Nginx. `/health` checks process health and `/ready` checks
dependencies.

## CMS

Use a custom Next.js CMS presentation over NestJS Content commands. Protect
admin access strongly before exposing privileged features. Sprint 0
implements an inert shell only; no Strapi runtime or separate CMS DB.

## PostgreSQL/PostGIS

Initial canonical SQL storage and PostgreSQL-backed sessions, with separate
application database with independently owned Content tables. Persistent NVMe volume; daily logical
backups plus base backups and frequent WAL archival for the one-hour DB RPO; encrypted off-server copies; controlled migrations; regular
restore tests.

## Redis

Separate evictable cache/rate-limit and persistent no-eviction queue
instances. Sessions remain in PostgreSQL; durable outbox work survives queue
loss. Configure persistence and resource bounds explicitly.

## OpenSearch

Persistent local volume and explicit heap sizing. Indexes are derived
and rebuildable; never canonical.

## Local Storage --- Phase 1

Storage abstraction methods: `put`, `get`, `delete`, `getPublicUrl`,
`getSignedUrl`.

Providers: `LocalStorageProvider`, later `S3StorageProvider`.

Paths: - `/srv/visitspakistan/storage/public/images` -
`/srv/visitspakistan/storage/public/video` -
`/srv/visitspakistan/storage/private/partner-verification` -
`/srv/visitspakistan/storage/tmp`

Use randomized object keys, MIME/type validation, limits and image
processing. Private files are never directly served by Nginx. Database
stores provider/object key/metadata, not absolute filesystem paths.

## S3 --- Optional Authorized Future Phase

Configure S3 provider → copy objects preserving keys → checksum
validation → switch new uploads → CDN for public media → signed access
for private objects → retire local primary only after verification.
Because URLs are generated by StorageService, business records should
not require mass rewriting.

## Nginx

Routes `/` to frontend/SSR, `/api/` to NestJS, protected CMS admin to
the custom Next.js CMS and only approved public media to local storage. Handles TLS,
compression, body-size limits, rate limiting, caching and security
headers.

## CI/CD

Checkout → locked install → lint → typecheck → unit/integration tests →
build → container build → dependency scan → staging deploy → smoke test
→ manual production approval → backup → production deploy → safe
migrations → health test → rollback if unhealthy.

## Deployment/Rollback

Use immutable versioned image tags and timestamped releases. Destructive
DB changes use expand/migrate/contract. Rollback restores prior
application image and compatible configuration/schema path.

## Observability

Structured JSON logs, Nginx logs, host CPU/RAM/disk, container health,
API latency/errors, PostgreSQL slow queries/connections, Redis memory,
OpenSearch heap/index health and backup status. Prometheus/Grafana/Loki
or equivalent can be added without changing application design.

## Security

TLS, deny-by-default firewall, SSH keys, least-privilege users, secrets
outside repo, RBAC, ownership checks, private verification documents,
dependency scans and upload validation. RBAC governs permissions with
resource ownership checks; login uses verified email/password, secure
revocable sessions and mandatory staff MFA. See
[implementation defaults](../02-architecture/implementation-defaults.md).

## Scaling Triggers

Move media to S3/CDN first, then database, OpenSearch and Redis to
dedicated/managed infrastructure as evidence requires; add multiple
API/frontend nodes behind a load balancer only when availability/load
justifies it.

Sprint 0 is local development infrastructure, not the production deployment
described above. [Local setup](../development/local-development.md) uses
native PostgreSQL and Compose Redis/OpenSearch; production operations remain
follow-up work.
