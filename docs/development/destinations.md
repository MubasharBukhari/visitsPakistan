# Destination vertical

See [ADR-0016](../adr/0016-destination-discovery-profiles.md), [implementation plan](../02-architecture/destination-implementation-plan.md) and [local setup](local-development.md).

Apply migrations with `pnpm db:migrate` and `pnpm db:migrate:test`, then run `pnpm db:seed`. Nine representative destination profiles (Hunza, Skardu, Islamabad, Lahore, Karachi, Swat, Chitral, Naran/Kaghan and Murree) are inserted as drafts with empty interests/seasons; rerunning seed preserves edits. Their canonical fixtures remain unverified, so the development directory starts empty until independently sourced data is published. This is intentional publication isolation, not a hardcoded empty page.

Start `pnpm dev:api` and `pnpm dev:web`. Website paths are `/destinations/` and `/destinations/{slug}/`. Public API paths are `GET /api/v1/destinations` and `GET /api/v1/destinations/{slug}`. Existing `/v1/destinations` paths remain compatibility aliases. The website uses the standard `/api/v1` paths. Swagger documents destination queries alongside editorial APIs.

Directory query parameters: `region` (REGION or PROVINCE_TERRITORY ancestor slug), `interest` (exact lowercase hyphenated tag), `season` (spring/summer/autumn/winter/all-year), `page` (1–10000), `pageSize` (1–48, default 12) and `locale` (default en). An all-year tag matches each named season; no suitable seasons are inferred from coordinates or CMS prose. Unknown query keys and malformed values return 422. Filters combine with AND. Unmatched filters/out-of-range pages return an empty data array with correct totals, not 404. Slug detail returns 404 for missing or ineligible destinations; infrastructure failure remains a service error.

Each card returns `canonical` (UUID, geographic identity, coordinates, timezone, provenance sources), interests, seasons, nearest eligible region, hierarchy, optional published destination editorial, sources and `last_verified`. The combined verification date is the older of canonical identity and discovery-profile verification. Detail adds `attractions`, `experiences`, restaurant `food`, `guides`, and empty structured `routes`, `itineraries`, `travel_products` collections. Canonical route/itinerary/cuisine/product owners are not implemented; route/itinerary/food editorial guides are explicitly separate and cannot imply a validated route or purchasable offer. Related entities and edges must have their own public eligibility. CMS snapshots are composed under the same repeatable-read transaction, and new editorial drafts do not replace the published snapshot.

SSR/no-store prevents stale publication/withdrawal. Public details render canonical/OpenGraph metadata, TouristDestination and BreadcrumbList JSON-LD, visible breadcrumbs, guide/directory links and credited sources. Filter/page variants are noindexed and canonicalized to the directory. Set `SITE_URL` to the public origin. Source links allow HTTP/HTTPS only; JSON-LD escapes script-closing markup. Loading, empty, invalid-filter, unavailable and missing-destination states are implemented. No partner marketplace functionality is added.

Run `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:integration`, `pnpm build`, `pnpm format:check`. Synthetic Hunza/Skardu fixtures live only in the isolated `_test` database and are withdrawn after checks. Production interest vocabulary, season assignments and source freshness need data approval; this task does not approve fictional travel data.

Schema references: [TouristDestination](https://schema.org/TouristDestination), [BreadcrumbList](https://schema.org/BreadcrumbList).

For a local populated preview without approving development fixtures, run `pnpm destinations:preview` and start the built website (`pnpm nx run web:start`) in another terminal. The preview API uses the isolated test database and prints synthetic Hunza/Skardu URLs at `127.0.0.1:3000`. Stop the preview normally to withdraw its records and remove temporary images. Do not run this alongside integration tests or another API on the same port. A different project may bind IPv6 localhost; use the printed IPv4 addresses to reach this workspace. Never reset or replace that other application's process.

Directory loading uses a route group; detail eligibility is resolved before a streaming loading boundary so missing detail pages return HTTP 404. Destination card links show pending navigation feedback. The Next.js not-found and error states do not disguise service outages as missing travel data.

## Sprint 1 editorial and geography

[ADR-0017](../adr/0017-sprint-1-destination-editorial-geography.md) and [Sprint 1 plan](../02-architecture/sprint-1-plan.md) describe the incremental extension. The confirmed custom CMS implements destination presentation; Strapi is not deployed.

Canonical responses now include `parent_id`, optional `summary`, publication status, creation/update timestamps, latitude/longitude and GeoJSON Point. All coordinates are derived from the same PostGIS geography(Point,4326) value. Geography retains the existing GiST and parent/type indexes. Hierarchy tiers may skip absent levels; seeds do not invent cities between provinces and valleys. Naran/Kaghan is an explicitly unverified development discovery-area grouping, not a new administrative tier or asserted boundary.

Detail adds `geographic_parent` (immediate parent, or null if ineligible), `geographic_children` (up to 48 direct eligible children) and `related_destinations` (up to six eligible siblings). A child's `destination_slug` is only present when a public destination profile exists, so the website never links a neighbourhood to a nonexistent destination page. Children and parent have independent source/publication gates. Related destinations share the canonical immediate parent; no proximity, road access or travel-time claims are inferred.

In the CMS, open a destination editorial linked to its canonical GeoEntity UUID. The Destination presentation panel edits quick answer, overview, why visit, best time, travel tips and FAQ pairs. SEO, hero media, sources, author/reviewer and freshness remain existing revision fields. Save the draft, submit, have a different editor approve, then publish. Destination fields are optional for legacy snapshots; blank sections are omitted. New drafts copy the presentation without replacing the public snapshot. Submitted and published presentation is immutable at the database boundary. No coordinates, hierarchy or canonical names are duplicated in presentation JSON.

`editorial.destination` returns the published presentation or null. The destination page renders these sections and FAQs on the server, alongside facts, parent/hierarchy, eligible children/siblings and credited sources. Structured data describes the visible approved destination and breadcrumbs; FAQ content is not advertised as a guaranteed search rich result.

The seed now covers Pakistan, an editorial Northern Pakistan region, all seven requested provinces/territories and nine destination profiles. Coordinates remain explicitly approximate fixtures, verification null and status DRAFT. For an immediately populated visitor demonstration, use the isolated test-only preview command above; it publishes synthetic editorial with these sections without approving development/production facts. Production publication requires independent canonical/profile provenance and editorial approval.

SEO discovery routes: `/sitemap.xml`, `/robots.txt`, `/llms.txt`. The uncached sitemap includes homepage, directory and published English destination URLs, with actual entity/editorial update dates. API failures are not converted into an empty successful sitemap. Before 50000 URLs, introduce sitemap sharding and a bulk identity projection; this sprint's representative dataset and expected initial 300–500 pages use bounded public directory reads. Configure `SITE_URL` before building the deployment so metadata/discovery links use its public origin.

Sprint 2 now links eligible attraction-family Places and independent Experience concepts to their public detail pages. See [discovery development](discovery.md). Sitemap also includes these two published page families and the Things To Do directory, sharing the same 50000 URL guard.
