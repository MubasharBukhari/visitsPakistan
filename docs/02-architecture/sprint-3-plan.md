# Sprint 3 — unified search implementation plan

Preserve Sprint 1–2 domain owners and eligibility rules. Implement versioned destination/place/experience projections in `libs/search`, PostgreSQL projection/change tracking in `libs/database`, NestJS search composition and Next.js SSR results plus accessible debounced global autocomplete. Future content/partner/product/event families are registry descriptors only; no future index is created or populated.

PostgreSQL remains canonical. A transactional statement-trigger generation marker captures changes to canonical owners, graph/provenance and public presentation dependencies even when updated outside application services. A single leased/advisory-locked poller reads a public snapshot, compares deterministic hashes with a durable manifest, bulk-upserts changes and deletes withdrawn documents, then checkpoints only the observed generation after successful delivery. Failed deliveries retry; a newer generation stays dirty. Reconciliation is periodic and on-demand. Redis is unnecessary for durable indexing at the current scale.

Full rebuild writes fresh physical generation indexes and switches three versioned aliases atomically. Retain old generations for rollback; manual cleanup only after inspection. Concurrent changes leave the generation marker dirty for catch-up. One PostgreSQL session advisory lock serializes incremental sync/rebuild jobs without holding a canonical write transaction across HTTP calls. A rebuild failure never switches aliases or advances delivery state.

Public query uses bounded multi-match/phrase/exact-name and prefix fields, typo fuzziness, reviewed synonyms, canonical alternative names (including supplied Urdu/transliterations), eligible destination/ancestor context and optional geographic proximity. No language names, coordinates or commercial signals are invented. API obtains current eligible UUIDs/destination associations from PostgreSQL, constrains OpenSearch to those identities, and returns canonical current DTOs rather than stale stored text. Query/page/expansion bounds and dependency timeouts protect resources. Search outage returns an explicit 503. Search result pages are noindexed and excluded from sitemap.

Risks: identity prefilter and snapshot reconciliation are intentionally bounded at 20000 entities; replace with per-hit batch eligibility plus deeper pagination/bulk projection at measured scale. Global generation coalesces dependency changes; incremental HTTP writes are hash-diffed but snapshot reads are full at MVP scale. Content taxonomy/Urdu aliases require editorial governance; synonyms expand intent, never assert access/suitability. Single-node development OpenSearch is not a production security configuration.

Verification: at least 50 representative relevance cases with judged synthetic canonical documents and actual OpenSearch execution; exact/alias/Urdu/transliteration/typo/prefix/related-context quality; filters, pagination, empty/errors; withdrawal/retired sources/edge changes; bulk failure and retry, stale/reordered jobs, rebuild crash/catch-up and atomic alias handling; SSR grouped results and accessible responsive browser flow. Run install, migrate, lint, typecheck, unit/integration tests, build, format. Preserve existing databases and unrelated owner changes.

Implemented the three derived public index families, canonical eligibility composition, worker/rebuild/reconciliation commands, Swagger API, global autocomplete and SSR grouped search. Future families remain unpopulated. The 80-case relevance benchmark passed against live OpenSearch; full validation passed 81 unit tests, 171 integration tests, lint, typecheck, all 12 builds and formatting. Browser checks covered grouped results, typo/prefix suggestions, keyboard selection, empty states and responsive 320px/390px layouts. Normal isolated preview cleanup was verified. Applied ten migrations to development and test databases without resetting either. Docker/cloud deployment, production load and real traveler quality remain operational follow-up; see the search guide for limits and recovery.
